# 猫疼痛表情（FGS）照片分析工具：设计方案

最后更新：2026-11-05

## 1. 目标

用户上传一张猫的照片，系统按猫疼痛表情量表（Feline Grimace Scale, FGS）给出五项评分和文字说明，并在**原图上叠加面部关键点和评分面板**，生成一张竖版报告图，供保存或分享。不生成新图片。

参考：`ref/` 下的三张图（两张报告图样式、一张提示词）。

定位是**以娱乐为主的表情观察参考，不是诊断**。原则：**分数尽量给，宁可偏低；该有的提示给足**。所有界面和报告图都要带免责声明（“仅供娱乐和日常观察参考”），不使用“诊断”“医疗”等字眼。

## 2. MVP 范围

包含：上传照片 → 分析 → 显示报告图 → 保存。

不包含：历史记录、多只猫档案、前后对比、用户账号。

## 3. 已定的决策

| 事项 | 决定 | 原因 |
|---|---|---|
| 形态 | **Web 网站**，不做微信小程序 | 用户是个人主体，小程序的“深度合成/AI”类目只对企业开放 |
| 托管 | **Cloudflare Workers**（同一个 Worker 托管网页和后端接口） | 用户没有服务器；API Key 只放后端 |
| 报告图 | **竖版**，在浏览器端用 Canvas 绘制 | 适合手机；服务器不需要处理图片 |
| 总分计算 | 由**后端代码**计算，不让模型算 | 避免模型算术错误 |
| 照片存储 | 服务器**不保存**照片 | 简化隐私说明 |
| 首选模型 | **千问 `qwen3.8-flash`，关思考**（2026-11-05 起；第一步用的是 DeepSeek `deepseek-flash`） | 第二步对比中唯一点位基本可用的大模型，约 0.006 元/次、25 秒 |

### 已否决的方案

- **微信小程序 + 云开发**：主体资质不满足（见上）。
- **把图片补成正方形再发给模型**：实测没有改善，部分照片点位整片错位。
- **Cloudflare Workers AI 运行自定义模型**：只能用官方模型库，不能上传自己的模型。

## 4. 整体架构（第一步）

```
浏览器
  ├─ 选择照片 → 按 EXIF 摆正 → 缩放到长边 1280px → JPEG
  └─ POST /api/analyze
        ↓
Cloudflare Worker（本地用 wrangler dev 运行）
  ├─ 校验请求（格式、大小）
  ├─ 调用 DeepSeek（系统提示词 + 图片），要求输出 JSON
  ├─ 校验、清洗模型返回的数据
  └─ 计算有效分、折算总分、分档
        ↓
浏览器
  └─ Canvas 绘制竖版报告图（原图 + 关键点 + 评分面板）→ 保存
```

坐标统一用 0–1000 的归一化值，前后端都基于同一张缩放后的图片，避免换算错位。

## 5. 数据约定

模型输出（详见 `prompts/fgs_system.md`）：

```json
{
  "is_cat": true, "face_visible": true, "image_quality": "good|fair|poor",
  "facial_activity": "none|yawning|mouth_open|eating_grooming|sleeping",
  "head_support": "free|resting|shoulders_not_visible",
  "landmarks": [{"id": 1, "x": 312, "y": 205, "visible": true, "uncertain": false}],
  "fgs": {
    "ear_position":       {"score": 0, "evidence": "..."},
    "orbital_tightening": {"score": 1, "evidence": "..."},
    "muzzle_tension":     {"score": 0, "evidence": "..."},
    "whiskers_change":    {"score": 0, "evidence": "..."},
    "head_position":      {"score": "NA", "evidence": "..."}
  },
  "observations": "...", "suggestions": ["..."], "caveats": "..."
}
```

后端处理规则：

- 分数只接受 0、1、2，其他一律视为 `"NA"`。
- **按状态改分**（模型只负责识别状态，改分由代码完成，宁低勿高）：

  | 状态 | 处理 |
  |---|---|
  | 打哈欠 | 眼眶、口鼻、胡须按 0 分计 |
  | 张嘴（叫、哈气、喘气）、进食或舔毛 | 口鼻、胡须按 0 分计 |
  | 睡觉 | 眼眶按 0 分计 |
  | 头靠在物体上 | 头部姿态按 0 分计 |
  | 看不到肩部 | 头部姿态记 NA |

  改过的项在报告上标“已校正”，并保留模型原分（`model_score`）。
- 坐标超出 0–1000 的点视为不可见，不画。
- `is_cat` 或 `face_visible` 为 false 时，不出报告，提示用户换照片。
- 总分 = 有效项得分之和 ÷（有效项数 × 2）× 10，保留一位小数。
- 有效项少于 2 项时不给总分。
- 结论分三档：低于 3 分“未见明显疼痛表情”；3 到 5 分“边界区间，建议换几张照片再看，并留意食欲、精神和活动”；5 分及以上“超过参考线，建议请兽医评估”。文献中的镇痛干预参考线约为 4/10，上线前需对照原文核实，再决定分界。
- 提示框（`notices`）：改过分时说明原因并提醒“总分可能偏低”；只有 2–3 项可评估时提示参考性低；照片不清晰时提示。
- 规则只在 `web/public/fgs.js` 维护一份；Python 测试脚本通过 `web/scripts/apply_rules.mjs` 调用同一份代码。

## 6. 分阶段计划

### 第一步：纯 DeepSeek，本地跑通基础流程（已完成，2026-11-05）

- 网页 + Worker 后端 + DeepSeek + Canvas 报告图，在本机 `wrangler dev` 下完整可用。
- 关键点也由 DeepSeek 给出（已知不准，见第 7 节），先保证流程通。
- 验证结果：单元测试 7 项通过；浏览器端到端测试 3 张照片，两只猫出报告（11 秒、40 秒），狗图被拒绝并提示换照片；异常请求返回正确提示。

运行方法（在 `web/` 目录下）：

| 命令 | 作用 |
|---|---|
| `npm install` | 安装依赖（首次） |
| 把 `DEEPSEEK_API_KEY=...` 写进 `web/.dev.vars` | 本地密钥，不提交 |
| `npm run dev` | 启动本地服务，浏览器打开 http://localhost:8787 |
| `npm test` | 单元测试（不调用 API） |
| `npm run e2e -- <照片>...` | 用本机 Edge 上传照片并保存报告到 `outputs/e2e/`（每张调用一次 API） |

### 第二步：对比不同模型，选定主用和备用

- 后端把模型调用抽象成可配置的“提供方”（接口地址、模型名、Key）。
- 候选（具体型号和价格待核实）：DeepSeek、通义千问 VL（阿里云百炼）、豆包视觉（火山方舟）、智谱 GLM-V、Kimi 视觉；海外模型视国内可用性再定。
- 用同一批测试照片、同一份提示词，比较：点位准确度、评分稳定性、误报（打哈欠/张嘴）、拒绝非猫图片、耗时、单次费用、失败率。
- 同时改进评分规则（见第 7 节“待改进”）。

### 第三步：考虑专用关键点模型

- 候选：`hugocornellier/cat-face-landmarks`（CatFLW 48 点，TFLite，找脸 17 MB + 定位 11 MB）。本地实测定位效果远好于 DeepSeek，正脸、长毛、深色、张嘴、头部倾斜都基本正确；纯侧脸不行；不会拒绝非猫图片。
- **授权限制：权重为 CC BY-NC 4.0，禁止商用**；商用需联系海法大学 Tech4Animals 实验室。必须署名数据集作者。
- 运行方式倾向放在**服务器端**（用户不下载模型）：
  - 首选 Cloudflare Containers（需 Workers 付费套餐，每月 5 美元）；
  - 备选国内云函数（阿里云/腾讯云）；
  - Hugging Face Spaces 只适合测试（空闲休眠、唤醒可能报错）。
- 定位和 DeepSeek 评分可以并行，不增加总等待时间。

## 7. 测试结论（2026-11-05，DeepSeek `deepseek-flash`）

测试照片：`test_photos/`，用户照片 1 张 + Wikimedia Commons 13 张（来源和授权见 `test_photos/SOURCES.md`）。共 47 次调用。

| 项目 | 结果 |
|---|---|
| JSON 输出 | 基本可用；纯侧脸黑猫曾把 8000 token 全部用于思考，没有返回结果 |
| 关键点 | **不可用**：12 张中 2 张较好、3 张勉强、7 张明显偏移或挤成一团 |
| 评分稳定性 | 6 张重复测试的照片中 3 张的结论在 4 分线上下跳动 |
| 误报 | 打哈欠的照片曾得 4 分，被提示“建议尽快请兽医评估” |
| 拒绝非猫 | 狗图 2 次都被拒绝（只测了 1 张） |
| 耗时 | 通常 11–35 秒，最慢 49 秒 |
| 费用 | 约 0.02–0.04 元/次（默认开启思考，输出 3000–7000 token） |

**注意**：测试照片都没有兽医评估，基本没有疼痛样本，只能说明稳定性，不能证明评分准确。

## 8. 风险和待定事项

| 风险 | 说明 | 应对 |
|---|---|---|
| 国内访问 | Cloudflare 免费版没有国内节点；`*.workers.dev` 默认域名在国内基本打不开 | 绑定自有域名；上线前用三大运营商网络实测 |
| 微信内打开 | 未备案域名可能被微信拦截 | 引导分享报告图，图上印网址 |
| 接口被盗刷 | 公开网站没有登录，任何人都能调用 | 已做：算力验证、按 IP 限次、全站每日上限（见第 8.1 节）。部署前还需：千问账户少量余额 + 余额预警，网站单独用一个 Key |
| 合规 | 绕开小程序审核不等于免除面向公众提供 AI 服务的义务 | 公开推广前咨询专业人士 |
| 评分依据 | 已核实：Evangelista 等 2019 年发表于 Scientific Reports，五项各 0–2 分，总分（满分 1）> 0.39 建议镇痛，约合 4/10 | 本工具“超过参考线”定在 5 分（宁低勿高），4.0–4.9 显示为边界区间；如需与论文一致，把 `HIGH_FROM` 改为 4 |
| 免费套餐 CPU | 免费版每次请求 10ms CPU，转发图片可能不够 | 部署时实测，不够就升级付费版 |

### 8.1 防滥用（2026-11-05 已实现）

接口只接受图片、提示词固定在后端，不能被当成通用 AI 接口使用；主要风险是被脚本反复调用消耗余额。

| 层 | 做法 | 配置（`web/wrangler.jsonc`） |
|---|---|---|
| 全站每日上限 | 每天最多 300 次（北京时间 0 点重置），最大损失约 2 元/天 | `DAILY_LIMIT` |
| 按 IP 限次 | 每 10 分钟 5 次、每天 20 次；IPv6 按 /64 网段计 | `IP_LIMIT_10MIN`、`IP_LIMIT_DAY` |
| 算力验证 | 前端先领题（`GET /api/challenge`，带签名、5 分钟有效），在浏览器里找到使 SHA-256 前 17 位为 0 的答案（电脑约 1 秒、手机 1–3 秒），随照片提交；每道题只能用一次 | `POW_DIFFICULTY`，签名密钥 `CHALLENGE_SECRET` |
| 账户兜底 | 千问账户只放少量余额、开余额预警；网站专用 Key，泄露可作废 | 阿里云后台 |

- 计数用 SQLite 版 Durable Object（`Guard`，免费套餐可用），全站一个实例，判断和记账之间没有 await，是原子的。计数服务出错时拒绝调用（宁可暂停也不多花钱）。
- 次数在调用模型前就记上，模型调用失败也算一次（偏保守）。
- 没用 Cloudflare Turnstile：官方文档说明中国大陆不支持。没用 Workers Rate Limiting 绑定：它按机房近似计数，周期只能是 10 或 60 秒。
- 已验证：单元测试覆盖题目签发与校验、重复使用、三种限次、北京时间换日、IPv6；本地集成检查确认无答案/篡改/重复使用返回 403，超限返回 429，浏览器端完整流程正常。
- 部署时要设置密钥：`wrangler secret put QWEN_API_KEY`、`wrangler secret put CHALLENGE_SECRET`（随机 64 位十六进制串）。

## 8.2 多语言（2026-11-05）

- 支持中文、英文。首次访问按浏览器首选语言（`zh*` → 中文，其他 → 英文），右上角按钮手动切换，选择记在本机浏览器（localStorage）。
- 界面、报告图、错误提示的文字都在 `web/public/i18n.js`。后端错误返回 `code`（前端按当前语言翻译）和对应语言的 `error` 文字；评分规则只返回代码（分档 `level`、提示 `notices`、改分原因 `reason`）。
- 模型写的观察文字：前端请求时带 `?lang=`，后端在用户消息里要求模型用该语言写。分析完再切换语言，报告上的界面文字会跟着变，模型写的部分保持原语言。
- 报告图换行：英文按整词，中文逐字，并避免标点出现在行首。
- 测试：`npm test` 检查中英文 key 和占位符一致、规则代码都有翻译；`npm run e2e:i18n`（不调用 API）检查自动选择、切换后刷新保持、手机宽度无横向溢出；`E2E_LOCALE=en-US npm run e2e -- <照片>` 测英文完整流程。
